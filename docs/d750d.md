# d750d: the daemon that owns the radio's serial port

## What it is for

d750d is the only program that opens the TM-D750's serial port. Every other tool in this project,
and every Hamlib program you point at the radio, talks to d750d over a local network port instead.
That keeps two programs from fighting over one port, and it lets d750d enforce the safety rules
below in one place. (A daemon is a program that runs in the background. See the
[glossary](glossary.md) for other terms on this page.)

d750d runs as a systemd user service. systemd is the Linux service manager, and a user service is
one it starts for you, not for the whole machine. [Install](install.md) sets it up.

## Before you start

- The radio is on and its USB cable is plugged in. The radio shows two USB serial ports. d750d opens
  `/dev/d750-cat`, which is the control head's port (USB id 2166:9030). The other port, the base
  unit's (USB id 2166:9032), is `/dev/d750-tnc` and belongs to [d750-aprs](aprs.md). The udev rule
  (`config/60-d750ctrl.rules`) creates both names. udev is the part of Linux that names devices when
  you plug them in. `sudo ./install-udev.sh` installs the rule once. See [Radio
  setup](radio-setup.md).
- The radio's CAT port must carry only CAT. CAT is the radio's command language over the serial
  port. GPS sentences on that port slow every command to seconds. Set menu 403 to Off, or run
  `d750 gps output off`.

## Try it

The sample output on this page was captured from the simulator, a pretend radio, not from a real
one. See [Try it without a radio](try-without-a-radio.md).

Ask the daemon what it is doing:

```sh
d750 state
```

```text
port open /dev/pts/0; not keyed; unlocked; last answer 18:48:20; unsolicited bytes seen 0
```

On a real radio the port is `/dev/d750-cat`. Send one Kenwood command through the plain command
port:

```sh
d750 raw ID
```

```text
ID TM-D750
```

Try a command the daemon refuses on that port:

```sh
d750 raw TX
```

```text
ERR TX is not allowed on this port
```

Stop all keying, then allow it again:

```sh
d750 lock
d750 unlock
```

```text
OK locked, PTT refused until unlock
OK unlocked
```

Read the daemon's log:

```sh
d750 log 12
```

```text
23:36:08 serial port /dev/pts/0 open
23:36:08 radio answers 'ID TM-D750'
23:36:08 unkey in 21 ms, radio said 'RX'
23:36:08 cmd client ('127.0.0.1', 39072): refused 'TX': TX is not allowed on this port
23:36:08 cmd 'TN 0,1' -> 'TN 0,1'
23:36:09 unkey in 20 ms, radio said 'RX'
23:36:09 cmd 'TN 2,1' -> 'TN 2,1'
```

(That is a trimmed copy of a longer log.) To check the service itself:

```sh
systemctl --user status d750d
```

## What it can do

d750d has no command line arguments and no help text. It is configured with environment variables
(see Settings below) and it starts with `python3 -I d750d.py`. Both of its ports listen on
`127.0.0.1` only, so nothing outside your computer can reach them.

### Port 4532: hamlib's NET rigctl protocol

Hamlib is a library that many radio programs use to control radios. Its NET rigctl rig speaks to a
rigctld server over the network, and d750d acts as that server. Programs such as xara, WSJT-X,
fldigi, GridTracker and OpenSlot, and any other Hamlib-aware program, can tune and key the radio
through it.

To point a program at it:

- Choose the rig "NET rigctl". On the command line that is rig model 2, as in
  `rigctl -m 2 -r 127.0.0.1:4532 f`, which prints the transmit band's frequency in hertz.
- Give it the address `127.0.0.1:4532`.

What d750d answers on this port:

- The opening handshake: `chk_vfo` and `dump_state`.
- Frequency: `f` and `F`. Mode: `m` and `M`. VFO: `v` and `V`. Keying: `t` and `T`. Split: `s` and
  `S` (accepted, with no effect). Levels: `l` and `L`.
- `get_vfo_info`, `get_powerstat` (always on), `get_lock_mode` (always unlocked), and the long names
  of the same commands, such as `get_freq`.
- VFOA is band A. VFOB is band B. The current VFO is the band that transmits.
- Modes are FM, FMN (narrow FM), AM and DSTAR. The names PKTFM and WFM are taken as FM, NFM as FMN,
  DV as DSTAR and PKTAM as AM.
- Levels are STRENGTH, RAWSTR, RFPOWER and SQL. RFPOWER reads as 1.0 for high, 0.5 for mid, 0.2 for
  low and 0.1 for EL. Setting it picks the nearest of those four. SQL is the squelch level from 0 to
  1.
- The frequency, mode and level commands act on the band that transmits. Setting the VFO with `V`
  changes which band transmits, so a program that selects VFOA or VFOB moves transmit to that band.
- `T 1` keys the radio, `T 0` unkeys it, and each is answered with `RPRT 0`. `T` takes exactly one
  value: 0 is off, and 1, 2 or 3 is on. Any other value, such as `T 4`, `T 00` or `T off`, and a `T`
  with no value or two values, is refused with `RPRT -1`.
- `F` and `L` take a number. A frequency or a level that is not a finite number, such as `inf` or
  `nan`, is refused with `RPRT -1` and never reaches the radio.
- A line may hold any character from 32 to 126, the printable ones. A line with a control character
  in it, or a line over 512 characters, is refused with `RPRT -1` and logged. The line end, a newline
  with at most one carriage return before it, does not count.

### Port 4533: the plain command port

This port takes one Kenwood command per line and returns the radio's one-line answer, or `ERR` and a
reason. The [d750 verbs](d750.md) and the [rig screen](d750ctrl.md) use it, and so does d750-aprs.

Before a line goes anywhere, d750d checks it whole. The line end, a newline with at most one
carriage return before it, is taken off first. Then the whole line is refused, and nothing of it
reaches the radio, when:

- it holds anything but letters, digits, the space and the five marks `, . - / +`. A carriage return
  inside the line, a semicolon, a tab and every other control character are refused this way;
- it starts with a digit, after any leading spaces;
- it is over 512 characters.

d750d judges a command by its first two characters, after any leading spaces, whatever follows them.
So `TX`, `TX0`, `TX 1` and ` tx` are all `TX`, and all refused.

It also understands five words of its own. Each acts only when it is the whole line, in small
letters: `lock` locks, but `LOCK`, `Lock`, ` lock` and `lock now` are refused.

- `state`: the one-line state shown above.
- `lock`: refuse keying until `unlock`. It always sends the radio the unkey command and checks the
  answer, whether or not the radio was keyed. See [What lock
  covers](#what-lock-covers-and-what-it-does-not).
- `unlock`: allow keying again.
- `reconnect`: close the serial port and open it again.
- `quit`: end this connection.

### What it refuses

- Port 4533 never passes these commands to the radio: `TX` (key), `RX` (unkey), `UP` and `DW` (the
  microphone's up and down keys), `SR` (reset the radio), `PS` (power off), `BE` (which can send an
  APRS beacon), `0M` (programming mode) and `0G` (service mode). `0M` and `0G` start with a digit, so
  the digit rule refuses them first. The answer is `ERR` and a reason. Only port 4532 may key, and
  only with `T`.
- Port 4533 refuses a line that breaks the rules in [Port 4533](#port-4533-the-plain-command-port).
  Each refusal has its own words. These were captured against the simulator:

```text
ERR TX is not allowed on this port
ERR a line may not start with a digit
ERR say the word alone, in small letters
ERR only plain letters, digits, spaces and , . - / + are allowed
ERR the line is longer than 512 characters
```

- While the daemon is locked, `T 1` on port 4532 is refused with `RPRT -1`, and port 4533 refuses
  three more commands, each with its own words:

```text
ERR VX is refused while PTT is locked
ERR TN is refused while PTT is locked
ERR PT is refused while PTT is locked
```

- A frequency, mode or level the radio itself refuses (it answers `N` or `?`) is an error to the
  client, and is logged.

### What lock covers, and what it does not

`lock` is for "nothing from this computer may start a transmission". While it holds:

- `T 1` on port 4532 is refused, so no Hamlib program, xara, d750-sstv or d750-rtty can key.
- `VX` with any value but 0 is refused, so VOX cannot be turned on. `VX` and `VX 0` still pass.
- `TN` with a value whose first number is not 0 is refused, so the TNC cannot be put into APRS or
  KISS mode. `TN` and `TN 0,1`, which turns the TNC off, still pass.
- `PT` with any value is refused, so the beacon method cannot be changed. `PT` alone still passes.

`lock` changes no setting itself. It does not cover:

- What is already set. VOX that was on stays on, and a TNC already in APRS or KISS mode stays in it.
  Run `d750 vox off` or `d750 tnc off` first if you want those off too.
- KISS frames. d750-aprs, and the KISS programs it serves, send frames to the TNC on its own USB
  port, not through d750d. Lock does not stop a frame sent through a TNC already in KISS mode. Use
  `d750-aprs transmit off` for that. See [d750-aprs](aprs.md).
- The radio's own front panel and microphone.

One more thing follows from it. While locked, the TNC cannot be put back in KISS mode, by anything:
after the radio restarts, d750-aprs's TNC reset turns the TNC off and is then refused, so the TNC
stays off and APRS stops until you unlock. `d750 tnc kiss` and `d750 fixup` are refused the same
way. Unlock, then run `d750 tnc kiss B` or `d750 fixup`.

`lock` always sends the unkey command and checks that the radio says it is receiving. When the
radio does not say so, the lock still holds, and the answer and the log say what happened:

```text
OK locked; the radio did not say it is receiving
```

The log line is "lock: locked, but the radio did not say it is receiving". Check the radio, and run
`d750 state`.

### When it unkeys by itself

d750d unkeys the radio:

- when it starts;
- when a client on port 4532 disconnects, keyed or not;
- when the serial port gives an error;
- when you send `lock`, keyed or not;
- 30 seconds after the radio was keyed, whatever the client does. A program that needs to transmit
  longer must send `T 1` again at least every 30 seconds. d750-sstv and d750-rtty do it every 15
  seconds;
- when you stop the daemon from a terminal with Ctrl+C.

An unkey counts only when the radio answers that it is receiving. Until it does, d750d still counts
the radio as keyed: `d750 state` says keyed, and once 30 seconds have passed since the key, the
watchdog sends the unkey again every second until the radio confirms. When the watchdog, a lock or
a client leaving gets no confirmation, the log says "unkey not confirmed" and why, once, and then
counts the repeats. An unkey from `T 0` is logged with what the radio said.

`d750 ptt off` unkeys at once, by sending `T 0` to port 4532.

### What it logs, and where

The log is `~/.local/share/d750ctrl/log/d750d-YYYY-MM-DD.txt`, with one file per day, and every line
starts with the time. d750d also prints each line to its own output, which
`journalctl --user -u d750d` shows. It logs:

- keying and unkeying, with the milliseconds the radio took to answer;
- every command that changes the radio, and every command the radio refused;
- lines refused on port 4533, and lines refused on port 4532 for a control character or their
  length, each with the reason, such as
  `cmd client ('127.0.0.1', 39072): refused 'TX': TX is not allowed on this port`. A control
  character shows as its code with two backslashes, such as `'ID\\x0dTX'` for a carriage return
  between `ID` and `TX`. A line refused for its length shows as `''`;
- errors, and the serial port opening and closing;
- bytes the radio sends without being asked. An APRS packet printed on the CAT port is logged as one
  line, "APRS packet on the CAT port", and dropped. Other unasked bytes are logged as a count and
  the first 40 bytes, and discarded.

It leaves out the routine reads the radio answered, such as the frequency or the busy flags. The
same error again is logged once, and then counted: one line a minute says how many more there were.
After a quiet minute the next one is logged in full again. Set `D750_LOG_ALL=1` to log every
exchange.

## Settings

d750d reads no settings file. These environment variables change it, and the list is the whole
interface:

- `D750_PORT`: the serial device. Default `/dev/d750-cat`.
- `D750_PTT_PORT`: the Hamlib port. Default `4532`.
- `D750_CMD_PORT`: the command port. Default `4533`.
- `D750_LOG_DIR`: the log folder. Default `~/.local/share/d750ctrl/log`.
- `D750_BAUD`: the serial speed. Default `9600`.
- `D750_LOG_ALL`: any value except empty, `0`, `no`, `off` or `false` logs every exchange. Default
  is off.

The service file that `install.sh` writes sets none of them. The tests set them to run a second
daemon on ports 4542 and 4543 against the simulator. To set one for the real service, use a systemd
drop-in (`systemctl --user edit d750d`, then add an `Environment=` line), because `install.sh`
rewrites the service file each time it runs. The other tools find the ports from `ptt_port` and
`cmd_port` in `d750ctrl.conf`; see [Settings](settings.md).

## When something goes wrong

- **You see:** `ERR d750d is not answering on 127.0.0.1:4533 (systemctl --user status d750d)`, or
  the rig screen says "Fail: d750d is not answering".
  - **Why:** the daemon is not running.
  - **What to do:** run `systemctl --user status d750d`. Start it with
    `systemctl --user start d750d`, and read `journalctl --user -u d750d` if it stops again.

- **You see:** `radio port not available` in answers, or "serial port closed" in the log.
  - **Why:** the radio is off, the cable is out, or `/dev/d750-cat` is missing because the udev rule
    is not installed. d750d starts without the radio and opens the port when it appears.
  - **What to do:** run `d750 doctor`. Check the cable and run `sudo ./install-udev.sh` if the name
    is missing. After the radio is back, `d750 fixup` puts back the settings the tools rely on.

- **You see:** every command takes seconds, or `d750 doctor` says "unsolicited bytes on the CAT
  port".
  - **Why:** the radio is sending GPS sentences, or other bytes nobody asked for, on the CAT port.
  - **What to do:** set menu 403 to Off (or check menu 982), or run `d750 gps output off`.

- **You see:** `RPRT -1` when a program tries to key, or "locked: PTT refused" in the log.
  - **Why:** the daemon is locked. A `T` with a value other than 0 to 3 gets `RPRT -1` too, as does
    a line with a control character in it or over 512 characters, or a frequency or level that is
    not a number.
  - **What to do:** run `d750 state`. If it says locked, run `d750 unlock`. Lock it again with
    `d750 lock` whenever you want no transmitting. If it says unlocked, check what the program
    sends; the log names refused lines.

- **You see:** `ERR TX is not allowed on this port`, or the same words with `RX`, `UP`, `DW`, `SR`,
  `PS` or `BE`.
  - **Why:** those commands key, unkey, move or reset the radio, or can send a beacon. d750d judges
    the first two characters, so `TX0` is refused the same way.
  - **What to do:** key through port 4532 with a Hamlib program, unkey with `d750 ptt off`, and use
    the radio itself for the rest.

- **You see:** `ERR a line may not start with a digit`.
  - **Why:** no command the tools use starts with a digit, and `0M` and `0G` enter the radio's
    programming and service modes.
  - **What to do:** nothing; d750ctrl never needs those modes.

- **You see:** `ERR say the word alone, in small letters`.
  - **Why:** a daemon word was sent in capitals, with spaces around it, or with more after it, such
    as `LOCK` or `lock now`.
  - **What to do:** send the word alone, in small letters: `d750 lock`, `d750 unlock` and
    `d750 state` do that.

- **You see:** `ERR only plain letters, digits, spaces and , . - / + are allowed`.
  - **Why:** the line held another character: a carriage return inside the line, a semicolon, a
    tab, another control character, or a mark such as `_` or `*`.
  - **What to do:** send one command per line, with nothing but those characters. A program that
    ends its lines with a carriage return and a newline is fine.

- **You see:** `ERR the line is longer than 512 characters`.
  - **Why:** no Kenwood command is that long.
  - **What to do:** check what the program sends; it is not a command.

- **You see:** `ERR VX is refused while PTT is locked`, or the same words with `TN` or `PT`.
  - **Why:** the daemon is locked, and that change would let the radio send by itself: VOX on, the
    TNC in APRS or KISS mode, or a beacon method. See [What lock
    covers](#what-lock-covers-and-what-it-does-not).
  - **What to do:** run `d750 unlock` first if you want the change, then lock again.

- **You see:** `OK locked; the radio did not say it is receiving` from `d750 lock`.
  - **Why:** the radio did not answer the unkey command with RX. The lock holds all the same.
  - **What to do:** look at the radio, and run `d750 state` and `d750 log`. If it is still
    transmitting, switch it off.

- **You see:** the radio unkeys by itself after 30 seconds.
  - **Why:** that is the watchdog. See "When it unkeys by itself".
  - **What to do:** have the program send `T 1` again within every 30 seconds.

- **You see:** the radio and everything else on the USB bus drop out, or the radio restarts.
  - **Why:** a transmitting handheld near the USB leads can reset the bus. After the radio restarts,
    its TNC may take commands but send nothing.
  - **What to do:** keep transmitting handhelds away from the leads. See [d750-aprs](aprs.md), which
    resets the TNC after the radio comes back, and [Troubleshooting](troubleshooting.md).
