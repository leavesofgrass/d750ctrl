# d750: the verbs, plain commands for the radio

## What it is for

`d750` is one command with many verbs. Each verb asks the radio something or changes one thing, and
prints the answer as short plain lines, the answer first. It suits a screen reader or a Braille
display, and it works in scripts. It talks to the radio through [d750d](d750d.md), the daemon that
owns the serial port.

## Before you start

- d750d is running and the radio is on. `d750 doctor` checks both and more.
- `d750 doctor`, `d750 fixup`, `d750 level` and `d750 record` use Linux tools you may need to
  install: `lsusb`, `systemctl`, `pactl`, `parecord` and, for Bluetooth checks, `bluetoothctl`.
  `d750 vara cq` and `d750 vara beacon` also need `nc` (netcat).
- Terms such as CAT, TNC and KISS are explained in the [glossary](glossary.md).

## Try it

The sample output on this page was captured from the simulator, a pretend radio, so the frequencies
and channels are made up. See [Try it without a radio](try-without-a-radio.md).

Look at both bands:

```sh
d750 status
```

```text
band A: 147.040 MHz, FM, squelch 6, busy, power high
band B: 144.390 MHz, FM, squelch 3, quiet, power mid, transmits, control
tnc: KISS on band B
daemon: port open /dev/pts/0; not keyed; unlocked; last answer 18:48:19; unsolicited bytes seen 0
```

See what a change would do, without doing it (`-n`):

```sh
d750 freq A 146.520 -n
```

```text
before: band A 147.040 MHz
would send: FQ 0,0146520000
```

Make the change:

```sh
d750 freq A 146.520
```

```text
before: band A 147.040 MHz
after: band A 146.520 MHz
```

See what the radio does when you ask for something it will not do:

```sh
d750 freq A 27.000
```

```text
before: band A 146.520 MHz
Fail: the radio refused: FQ 0,0027000000 -> N
```

## What it can do

The verbs are grouped as `d750 help` groups them. The full help text is at the end of this section.

### Dry runs and exit codes

- Add `-n` anywhere on the line to do a dry run of a verb that changes the radio. The verb reads
  what it needs, prints what it would send, and sends nothing. The line "would send:" shows the raw
  command.
- The exit code is 0 for Pass, 1 for Fail and 2 for a usage mistake, such as an unknown verb or a
  missing argument. A usage mistake prints "usage:" and the form of the verb. This holds for every
  verb, so a script can trust the code.
- A radio command that the radio answers with `N` or `?` is a Fail. A daemon that is not running is
  a Fail, with the line `ERR d750d is not answering`.

Bands are written `A` or `B` (or `0` or `1`). Verbs print their lines to the screen; failures go to
the error output.

### Looking

- `d750 status`: both bands, the transmit band, the TNC and the daemon's state. Each band line gives
  frequency, mode, squelch, busy or quiet, power, and the words "transmits" and "control" for the
  band that has them. See the example above.
- `d750 busy A|B`: whether that band's squelch is open now. It prints `band B: quiet` or
  `band B: busy`.
- `d750 watch A|B [SECONDS]`: reads the busy flag once a second for SECONDS (default 30) and prints
  a line only when it changes, then how many times the squelch opened.

```sh
d750 watch B 3
```

```text
band B busy state once a second for 3 s; a line only when it changes
18:48:21 busy
squelch opened 1 times in 3 s
```

### Tuning

- `d750 freq A|B MHZ`: set a band's frequency, in megahertz. It prints before and after.
- `d750 band A|B`: make that band the control band and the transmit band. It prints
  `control and transmit band: B`.
- `d750 mode A|B fm|nfm|am|dv`: set the mode. It prints `band A mode: NFM`. The radio accepts only
  those four. The radio's DR mode cannot be reached this way.
- `d750 squelch A|B 0-9`: set the squelch level. It prints `band B squelch: 4`.
- `d750 power A|B high|mid|low|el`: set the output power. The words `h`, `m`, `medium` and `l` also
  work. Until you have run `d750 probe`, it first prints a note that the power command is not yet
  verified on your radio.

```sh
d750 power A low
```

```text
note: PC not yet verified on this radio; run d750 probe when it is plugged in
band A power: low
```

Changing the transmit band, frequency, mode or power does not transmit. Keep in mind that the next
program that keys the radio will use what you set.

### Memories

These verbs work on the radio's memory channels. The channels in the examples are made up by the
simulator.

- `d750 mem list [FROM TO]`: the channels from FROM to TO (default 0 to 49) that hold something.
- `d750 mem show N`: one channel, field by field.
- `d750 mem goto A|B N`: recall channel N on that band.
- `d750 mem export FILE [FROM TO]`: save channels to FILE as raw lines (default 0 to 999, which
  takes a while). The file starts with a comment line and has one `ME` line per channel.
- `d750 mem import FILE`: write a file from `mem export` back to the radio. This overwrites those
  channels on the radio. Use `-n` first; it prints each line it would send. It prints how many were
  written and how many the radio refused, and the exit code is 1 if any were refused.

```sh
d750 mem list 0 5
```

```text
note: ME not yet verified on this radio; run d750 probe when it is plugged in
channels 0 to 5 that hold something:
  000: 146.520 MHz, FM, offset 0.000 MHz
  001: 144.390 MHz, FM, offset 0.000 MHz
```

```sh
d750 mem show 0
```

```text
channel: 000
frequency: 146.520 MHz
offset: 0.000 MHz
step: 2
txstep: 2
mode: FM
fine: 0
finestep: 0
tone: 0
ctcss: 0
dcs: 0

reverse: 0
oddsplit: 0

tonefreq: 08
ctcssfreq: 08
dcscode: 000

```

```sh
d750 mem goto A 1
```

```text

```

### GPS, VOX and clock

- `d750 gps`: whether the radio's GPS is on, and whether it sends GPS sentences to the PC port.
- `d750 gps output off|on`: switch the PC output. Keep it off: sentences on the CAT port slow every
  command to seconds.
- `d750 vox [on|off]`: with no argument, shows the VOX state, delay and gain. With an argument, sets
  VOX on or off and answers `VOX: on` or `VOX: off`.
- `d750 clock`: the radio's clock next to your computer's clock.
- `d750 clock set`: set the radio's clock from your computer. Try `d750 clock set -n` first.

```sh
d750 gps
```

```text
note: GP not yet verified on this radio; run d750 probe when it is plugged in
GPS on; PC output off
```

```sh
d750 clock set -n
```

```text
note: RT not yet verified on this radio; run d750 probe when it is plugged in
radio clock: 2026-11-17 18:48:25; this computer: 2026-11-17 18:48:25
would send: RT 261117184825
```

### Sound card

- `d750 level [SECONDS]`: listens to the radio's sound card for SECONDS (default 3) and prints the
  level in dBFS (decibels below the loudest value the card can hold). It ends with a reading in
  words: silence, clipping, hot (lower menu 913), good, or quiet (menu 913 could go up). Without the
  sound card it prints `Fail: the radio's sound card is not present`. If it recorded nothing, the
  exit code is 1.
- `d750 record SECONDS FILE [rx|tx]`: record the audio path to a WAV file. `rx` (the default) is
  what the radio hears. `tx` is what your computer is sending to the radio.

### TNC and VARA

The TNC is the radio's built-in packet modem. In KISS mode (a plain framing used between a TNC and a
computer) it hands packets to d750-aprs.

- `d750 tnc off|aprs|kiss [A|B]`: set the TNC mode, and optionally the band. It prints the mode
  before and after. `d750 fixup` keeps the mode and band you chose in `fixup.conf`.

```sh
d750 tnc kiss B
```

```text
before: off on band B
after: KISS on band B
KISS mode: the radio's own APRS screen is off; KISS is on /dev/d750-tnc
```

VARA is a modem for data over radio, and xara is the VARA-compatible modem that this project keys
through d750d. See [VARA, xara and chat](vara-and-chat.md) for the whole subject. The verbs:

- `d750 vara fm` or `d750 vara hf`: set xara's mode in its settings file and restart xara.
- `d750 vara off`: stop xara.
- `d750 vara status`: xara's state, the mode settings, its ports and the last time it keyed. It
  exits 0 when there is no daemon log yet.
- `d750 vara cq`: send one VarAC CQ frame through xara. **This transmits.**
- `d750 vara beacon`: send one VarAC beacon frame through xara. **This transmits.**

`cq` and `beacon` use the call in `mycall` (see [Settings](settings.md)). Run them with `-n` first.
The dry run names the transmit band and frequency and the frame it would send:

```sh
d750 -n vara cq
```

```text
transmit band B at 144.390 MHz
would send one VarAC cq frame through xara: CQFRAME N0CALL
```

```sh
d750 -n vara beacon
```

```text
transmit band B at 144.390 MHz
would send one VarAC beacon frame through xara: CQFRAME N0CALL-9
```

### Transmitting and safety

Nothing in this group transmits. The verbs here stop or prevent it. The only `d750` verbs that can
start a transmission are `vara cq` and `vara beacon`, in the group above.

- `d750 ptt off`: unkey the radio now. It prints `unkey: RPRT 0` when the daemon took it. If the
  radio does not confirm the unkey, it prints a line that starts with `Fail:` and the exit code is
  1.
- `d750 lock`: unkey, then refuse all keying until `d750 unlock`.
- `d750 unlock`: allow keying again.

```sh
d750 lock
d750 unlock
d750 ptt off
```

```text
OK locked, PTT refused until unlock
OK unlocked
unkey: RPRT 0
```

### Health and logs

- `d750 doctor`: the health checklist, one line per check, "Pass:" or "Fail:" at the start, and a
  total. The exit code is 0 only if nothing failed. The checks:
  - the radio shows on USB, and `/dev/d750-cat` is there;
  - d750d is running and its port is open, and the radio answers `ID`;
  - the radio's firmware and type, on a line such as `Pass: radio firmware 1.03, type K,2,1` (that
    is what the pretend radio answers). If the radio does not answer, a `note:` line says the
    firmware is not shown, and that is not a Fail;
  - the CAT port carries only CAT, and the GPS output to the PC is off;
  - the TNC mode, and that the data band's squelch is not 0 (with menu 508 on Busy, the TNC will not
    transmit while the squelch is wide open);
  - the radio's sound card is present, and is not your default sound output;
  - Bluetooth is paired, when you have set `bluetooth` in your settings;
  - the PTT port answers, and whether xara is running.
- `d750 probe`: asks the radio, read only, which commands it answers, and writes the table the other
  verbs rely on to `commands.txt` in your settings folder. It never sends the commands that key,
  reset or power off the radio. `d750 probe --show` prints the last table. Run it once when the
  radio is first connected; the "not yet verified" notes stop after that.
- `d750 fixup`: puts back what the other tools rely on, after a power cycle or a restart. It reads
  `fixup.conf` (it writes one with defaults the first time), checks the TNC mode, the data band's
  squelch and the GPS output, and changes what is wrong. Lines start with "Pass:", "Fixed:" or
  "Warn:".
- `d750 state`: only the daemon's state line, as shown on the [d750d page](d750d.md).
- `d750 log [N|follow]`: today's d750d log. With no argument, the last 20 lines. With N, the last N
  lines. `d750 log follow` follows it until you press Ctrl+C.
- `d750 raw CMD [ARGS]`: send one Kenwood command and print the radio's answer line. Keying is
  refused. It exits 0 when the radio answers, and 1 when the answer is an error.
- `d750 help`: the text at the end of this section.

```sh
d750 fixup
```

```text
Pass: radio answers ID TM-D750
Pass: tnc KISS on band B
Fixed: band B squelch 3 (was 4)
Pass: GPS on, PC output off
Pass: nothing unsolicited on the CAT port
Warn: the radio's sound card is not present
```

(The last line of the real output is a note about the Bluetooth address, trimmed here.)

```sh
d750 raw ID
```

```text
ID TM-D750
```

The daemon refuses the commands that key, unkey, reset or power off the radio:

```sh
d750 raw TX
```

```text
ERR TX is not allowed on this port; keying goes through 4532
```

A verb that does not exist prints the one-line reason and the help, and exits with code 2:

```sh
d750 nonsense
```

```text
unknown verb: nonsense
d750: control and configure the Kenwood TM-D750 through d750d.
Plain lines, the answer first.
Verbs:
Looking:
  status: both bands, transmit band, TNC, squelch, power, daemon state
  ...
```

## Settings

`d750` reads these from `~/.config/d750ctrl/d750ctrl.conf`: `mycall`, `bluetooth`, `cmd_port` and
`ptt_port`. It also keeps `fixup.conf` and `commands.txt` in the same folder. The environment
variables `D750_CMD_PORT`, `D750_PTT_PORT`, `D750_LOG_DIR` and `D750_CONF_DIR` override the
defaults. Everything is listed on the [settings page](settings.md).

## When something goes wrong

- **You see:** `ERR d750d is not answering on 127.0.0.1:4533 (systemctl --user status d750d)`.
  - **Why:** d750d is not running.
  - **What to do:** see [d750d](d750d.md).

- **You see:** `Fail: the radio refused: ... -> N`.
  - **Why:** the radio would not accept that value, such as a frequency it does not cover.
  - **What to do:** check the value. `d750 status` shows what is set.

- **You see:** `note: ... not yet verified on this radio; run d750 probe`.
  - **Why:** `d750 probe` has not run yet on this computer.
  - **What to do:** run `d750 probe` once, with the radio connected.

- **You see:** `Warn: the radio's sound card is not present`, or
  `Fail: the radio's sound card is not present` from `d750 level`.
  - **Why:** the control head's USB socket is not connected, or the computer does not see it.
  - **What to do:** connect it (through a data-only adapter or a powered hub; see [Radio
    setup](radio-setup.md)).

- **You see:** `Fail: no daemon log yet for today`.
  - **Why:** d750d has not logged anything today.
  - **What to do:** check that d750d is running.
